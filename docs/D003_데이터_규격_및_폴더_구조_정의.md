# D003. 데이터 규격 및 폴더 구조 정의

mintel 파이프라인이 사용하는 입출력 폴더 구조와, 각 단계에서 생성/소비되는 데이터의
규격(스키마)을 정리한 문서입니다. 실제 경로 정의는 `config.py` 한 곳에서 관리하며,
이 문서는 그 값들이 실제로 어떻게 쓰이는지를 설명합니다.

## 1. 전체 폴더 구조

```
mintel/
├── app.py                     # 전체 파이프라인 진입점 (1->2->3번 방 순서 실행)
├── config.py                  # 입출력 경로 상수 정의 (모든 경로의 단일 출처)
├── pipeline_ingestion.py      # ingestion 단계: 영상 -> Key-frame -> CLIP/YOLOv8/EasyOCR 가공
├── pipeline_storage.py        # storage 단계: 가공된 Key-frame -> Qdrant DB 적재
├── pipeline_inference.py      # inference 단계: 검색 -> 시각 검증 -> 최종 답변 생성 -> 결과 저장
├── modules/
│   ├── ingestion/             # CLIP 임베딩 / YOLOv8 객체 탐지 / EasyOCR / Key-frame 추출
│   ├── storage/               # Qdrant 연결 관리 + 결과 저장(ResultManager)
│   └── inference/             # 검색 엔진 / 키워드 매칭 / LLaVA 검증 / Llama-3 답변 생성
├── utils/
│   └── image_to_video.py      # PNG 시퀀스 -> mp4 변환 유틸 (파이프라인 흐름 밖의 보조 스크립트)
└── storage/                   # 실행 시 생성되는 모든 데이터 (config.STORAGE_DIR)
    ├── videos/                # [입력] 원본 .mp4 영상
    ├── frames/                # [ingestion 단계 출력] 추출된 Key-frame 이미지(.jpg)
    ├── db/                    # [storage 단계 출력] 로컬 Qdrant 벡터 DB 파일
    └── results/               # [inference 단계 출력] 실행 시각별 결과(JSON) + 실행 로그
```

폴더 경로는 전부 `config.py`에서 정의되며, 다른 곳에서는 이 상수만 참조합니다.

```python
BASE_DIR = Path(__file__).resolve().parent
STORAGE_DIR = BASE_DIR / "storage"

VIDEOS_DIR = STORAGE_DIR / "videos"    # ingestion 단계 입력
FRAMES_DIR = STORAGE_DIR / "frames"    # ingestion 단계 출력 / storage 단계 입력
DB_DIR = STORAGE_DIR / "db"            # storage 단계 출력 / inference 단계 입력
RESULTS_DIR = STORAGE_DIR / "results"  # inference 단계 출력
```

> `storage/` 하위의 실제 데이터(영상, 프레임, DB, 결과)는 용량이 크거나 실행마다
> 달라지므로 git에 커밋하지 않습니다(`.gitignore` 참고). 폴더 구조 자체는 각
> 폴더의 `.gitkeep`으로 유지됩니다.



## 2. `storage/videos/` — 원본 영상 (ingestion 단계 입력)

- **형식**: `.mp4`
- **탐색 범위**: `videos_dir` 하위 폴더까지 재귀적으로 탐색 (`list_video_files()`,
`modules/ingestion/keyframe_extractor.py`)
- **파일명 충돌 처리**: 서로 다른 하위 폴더에 동일한 파일명이 있어도, `videos_dir`
기준 상대 경로 전체를 이어붙여 고유 식별자(`video_identifier`)를 만들기 때문에
충돌하지 않습니다.
  - 예: `storage/videos/kitti/2011_09_26/data/sample.mp4`
  → 식별자 `kitti_2011_09_26_data_sample`



## 3. `storage/frames/` — 추출된 Key-frame (ingestion 단계 출력)

- **형식**: `.jpg`
- **파일명 규칙**: `{video_identifier}_frame_{frame_index:06d}.jpg`
  - 예: `sample_frame_000414.jpg` (원본 영상 `sample.mp4`의 414번째 프레임)
- **선별 기준**: 직전 Key-frame과의 HSV 컬러 히스토그램 상관계수가
`DEFAULT_SIMILARITY_THRESHOLD`(기본 0.90) 미만으로 떨어지고, 마지막 Key-frame
이후 `DEFAULT_MIN_FRAME_INTERVAL`(기본 10프레임) 이상 지났을 때만 새 Key-frame으로
저장됩니다 (`modules/ingestion/keyframe_extractor.py`).



### `KeyFrame` 데이터 클래스 (메모리 상에서만 존재, 파일로 직접 저장되지 않음)

```python
@dataclass
class KeyFrame:
    video_name: str            # video_identifier
    frame_index: int           # 원본 영상 기준 프레임 번호
    timestamp_sec: float       # frame_index / fps
    image: np.ndarray | None   # 저장 직후 None으로 비워짐 (메모리 절약)
    saved_path: Path | None    # storage/frames/ 안의 실제 저장 경로
    embedding: list[float] | None   # CLIP 이미지 임베딩 (길이 512)
    objects: list[str] | None       # YOLOv8이 탐지한 COCO 클래스명 목록
    texts: list[str] | None         # EasyOCR이 인식한 텍스트 목록
```

`embedding`/`objects`/`texts`는 `pipeline_ingestion.enrich_keyframes()` 단계에서
채워지며, 이 상태로 storage 단계에 전달되어 Qdrant에 저장됩니다.

## 4. `storage/db/` — Qdrant 로컬 벡터 DB (storage 단계 출력)

- Docker 없이 `QdrantClient(path=...)`로 구동되는 **로컬 파일 기반** DB입니다.
- 컬렉션 이름: `mintel_collection` (`modules/storage/qdrant_client.py`)
- 벡터 차원: `512` (CLIP `openai/clip-vit-base-patch32` 기준), 거리 함수: 코사인 유사도



### Qdrant 포인트 스키마

`pipeline_storage._keyframe_to_point()`가 `KeyFrame`을 아래 형태로 변환해 저장합니다.

```json
{
  "id": "<frame_path 기준 결정적(deterministic) UUID>",
  "vector": [0.0123, -0.0456, "... (길이 512)"],
  "payload": {
    "video_name": "sample",
    "frame_index": 414,
    "timestamp_sec": 13.8,
    "frame_path": "/절대/경로/storage/frames/sample_frame_000414.jpg",
    "objects": ["car", "truck"],
    "texts": ["STOP"]
  }
}
```

- `id`는 `uuid.uuid5(uuid.NAMESPACE_URL, frame_path)`로 생성되는 결정적 UUID라서,
같은 프레임을 다시 적재해도 point가 무한정 늘어나지 않고 덮어써집니다(idempotent).
- `objects`/`texts`는 inference 단계의 Dense+Sparse 하이브리드 검색에서 필터 조건으로
사용됩니다 (`modules/inference/search_engine.py`, `keyword_matcher.py`).



## 5. `storage/results/` — 실행 결과 (inference 단계 출력)

파이프라인을 실행할 때마다 현재 시각 기준 서브 폴더가 자동 생성됩니다.

```
storage/results/
└── 20260714_162100/         # YYYYMMDD_HHMMSS
    ├── result.json           # 검색+시각 추론이 끝난 최종 데이터
    └── run.log                # 해당 실행의 전체 콘솔 로그 (tee)
```



### `result.json` 스키마

```json
{
  "status": "success",
  "matches": [
    {
      "rank": 1,
      "video_source": "sample.mp4",
      "timestamp": "00:00:13",
      "frame_path": "./storage/frames/sample_frame_000414.jpg",
      "confidence_score": 0.94,
      "analysis_report": "LLaVA가 생성한 상세 설명"
    }
  ]
}
```


| 필드                           | 타입          | 설명                                                |
| ---------------------------- | ----------- | ------------------------------------------------- |
| `status`                     | string      | `success` | `no_match` | `error`                  |
| `matches[].rank`             | int         | `confidence_score` 내림차순 기준 순위 (1부터)               |
| `matches[].video_source`     | string      | 원본 영상 파일명 (`video_name` + `.mp4`)                 |
| `matches[].timestamp`        | string      | `HH:MM:SS` (프레임 인덱스/FPS로 역산된 `timestamp_sec`을 변환) |
| `matches[].frame_path`       | string      | 프로젝트 루트 기준 상대 경로 (`./storage/frames/...`)         |
| `matches[].confidence_score` | float       | Qdrant 벡터 유사도 점수 (0~1, 소수 2자리 반올림)                |
| `matches[].analysis_report`  | string      | LLaVA가 생성한 해당 프레임 상세 설명                           |
| `error_message`              | string (선택) | `status: "error"`일 때만 포함되는 예외 메시지                 |


- `status: "no_match"`인 경우 `matches`는 빈 배열입니다 (검색 결과가 없거나,
LLaVA가 모든 후보를 "존재하지 않음"으로 판정한 경우).
- `matches`에는 LLaVA가 `exists: true`로 검증한 프레임만 포함됩니다
(`ResultManager.build_matches(..., only_verified=True)`).



### `run.log` 형식

```
============================================================

```



## 6. `.gitignore`가 제외하는 데이터 (요약)


| 경로                                                                          | 이유                                             |
| --------------------------------------------------------------------------- | ---------------------------------------------- |
| `storage/videos/*`, `storage/frames/*`, `storage/db/*`, `storage/results/*` | 용량이 크거나 실행마다 달라지는 산출물 (폴더 구조만 `.gitkeep`으로 유지) |
| `*.pt`                                                                      | YOLOv8 등 자동 다운로드되는 모델 가중치                      |
| `__pycache__/`, `*.pyc`                                                     | 파이썬 바이트코드 캐시                                   |
| `.vscode/`                                                                  | 개인 로컬 IDE 설정                                   |
| `.DS_Store`                                                                 | macOS 파일시스템 메타데이터                              |


CLIP 모델(`openai/clip-vit-base-patch32`)은 프로젝트 폴더가 아니라
`~/.cache/huggingface/`에 캐시되므로 `.gitignore` 대상에 포함되지 않습니다.
